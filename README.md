# HOTEL RAG

Hotel RAG is a FastAPI/PostgreSQL application with a React/Vite chat UI. The
current chatbot keeps conversation slots in PostgreSQL and only recommends
hotel records marked `is_verified = true`. It does not claim live availability
or invent room prices.

## Current verified state

- Backend: FastAPI, SQLAlchemy, PostgreSQL.
- Frontend: React 19 and Vite 7; production build verified.
- Chat: Vietnamese greeting, location/date/guest/budget slot extraction,
  isolated saved sessions, lexical BM25 retrieval over verified hotel records,
  and citations.
- LLM, E5 model, and Qdrant are not currently running or installed. Replies
  identify themselves as `grounded_fallback`; this is not presented as an LLM
  answer.
- At the last read-only PostgreSQL check, `hotels` had 2 rows, `reviews` had 0,
  and no hotel was marked verified. The chatbot therefore correctly returns
  no verified recommendation until sourced data is added.
- No local dataset files or requested conversation workbook were found.

## Windows setup

From the project root in PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Set-Location .\frontend
npm.cmd ci
Set-Location ..
```

Node.js LTS was installed for this workspace machine. If `node` or `npm.cmd`
is not found in an existing VS Code terminal, restart VS Code or add
`C:\Program Files\nodejs` to that terminal's PATH.

## Database migrations

The application does not run schema migrations automatically. Apply these
PostgreSQL SQL files, in order, against the intended database after reviewing
them:

1. `backend/migrations/0001_reviews_user_id.sql`
2. `backend/migrations/0002_booking_status_default.sql`
3. `backend/migrations/0003_chat_memory.sql`

Migration 0002 checks for null booking statuses and aborts rather than altering
existing rows. Migrations have not been run automatically by the development
assistant. Do not use `create_tables.py` as a migration mechanism on an
existing database.

## Data pipeline

Keep downloaded originals immutable under `data/raw/`. The preprocessing CLI
accepts CSV, JSON, JSONL, XLSX, and XLSM files:

```powershell
.\.venv\Scripts\python.exe -m ml.preprocessing.pipeline --input-dir .\data\raw --output-dir .\data\processed\reviews
```

It normalizes Unicode, strips HTML, removes blank and duplicate reviews, records
source checksums, and writes a quality report. It never creates labels.

The ABSA trainer accepts explicitly labeled CSV files only. See
`ml/absa/baseline.py`; training is blocked until a compatible scikit-learn
environment and properly licensed labeled data are available.

## Qdrant and embeddings

An optional Qdrant client adapter and multilingual E5 embedder are under
`ml/rag/`. Optional dependencies are listed in `requirements-ai.txt`. They have
not been installed because the current Python is 3.15.2, available RAM was
about 1.8 GiB, and no Qdrant/Ollama service is active. The adapter reports a
clear error until dependencies and services are installed; current chat uses
BM25 and database records instead.

For a local Qdrant service where Docker is available:

```powershell
docker run --name hotel-rag-qdrant -p 6333:6333 -p 6334:6334 -v qdrant_storage:/qdrant/storage qdrant/qdrant
```

Configure `QDRANT_URL` (and `QDRANT_API_KEY` only when applicable) in the
environment. Never store credentials in source code.

## Safety and source policy

- Only verified hotel records are eligible for recommendations.
- Reviews are opinions, not evidence of official price, policy, or availability.
- A new booking remains `pending_confirmation`; no inventory integration is
  configured.
- The chatbot's deterministic fallback does not claim to be generated by an
  LLM.
- Dataset licenses and local presence are tracked in `DATASET_CATALOG.md`.
